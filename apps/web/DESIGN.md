## 0. 설계 원칙과 시그니처

1. **제안서가 곧 와이어프레임이다.** 화면의 모든 요소는 제안서 조항 하나를 증명한다.
   증명하는 조항이 없는 장식은 뺀다.
2. **시그니처 = "이음선과 출처 도장".** 답변의 모든 단계가 공식 출처에 "이어져" 있음을
   시각화한다. 이음선(점선)은 절차를 잇고, 출처 도장(초록 파선 테두리)은 검증을 증명한다.
   이 두 기호가 시민 화면과 이음센터를 하나로 관통한다.
3. **관료적 디테일이 실물감이다.** 기관 소속 표기, 대표전화, 운영시간, 감사 로그 고지,
   승인자 실명이 찍힌 도장 — 행정 요소들이 "진짜"를 만든다.

### 절대 하지 않는 것
- 그라디언트(스켈레톤 페이드 마감 제외), 네온, 다크모드, 글래스모피즘, 이모지 UI
- 토큰 스케일 밖의 임의 색·간격·반경·그림자
- Recharts 및 통계 차트 일체 (P1 범위 — Overview에 절대 추가 금지)
- 브라우저/프레임워크 기본 노출: Next.js 개발 뱃지, 기본 favicon, 기본 페이지 title
- 애니메이션: 허용 목록(11장) 외 전부 금지

## 2. 색 역할 고정 (전 화면 공통, 협상 불가)

| 색 | 역할 | 금지 |
|---|---|---|
| 남색 `--color-primary` | 기본 행동, 링크, 선택. **유일한 행동색** | 장식·강조 배경으로 남용 금지 |
| 초록 `--color-verify` | **검증·승인·출처에만** | 일반 성공 표시 금지 |
| 빨강 `--color-danger` | **오류·반려에만** | **폴백에 사용 금지** |
| 호박 `--color-warning` | 대기·주의 상태 뱃지, 주의 박스 | — |

- 본문 내 파란색 텍스트는 실제 링크에만 허용 (링크 오인 방지).
- 핵심 기한·수치 강조는 `<b>` + `--color-highlight` 배경(패딩 0 3px, 반경 4px)로 한다.
  예: "<b style="background:highlight">이사한 날부터 14일 이내</b>". 표시 계층에서 처리하고
  mock 데이터는 바꾸지 않는다.

## 3. 반경·간격·타이포·그림자 규칙

**반경은 토큰 스케일 8종만 사용한다.** (v2의 "12/8/6px 세 값" 조항을 이 조항으로 대체)

| 토큰 | 용도 |
|---|---|
| `--r-chip` 6px | 사유 코드·상태·판정 뱃지, 인라인 태그 |
| `--r-btn-s` 10px | 작은 버튼(테이블 행 액션, 뒤로가기), 사이드바 메뉴 항목, 필요 서류 칩 |
| `--r-btn` 12px | 버튼·입력창·CTA, 신뢰 배너, 주의 박스, 초안 정의 표 컨테이너 |
| `--r-cell` 12px | 정보 셀(처리 기간·수수료·담당 기관), 발단 질문 요약 박스 |
| `--r-card-s` 14px | 출처 블록, KPI 카드, 분야 카드, 예시 질문 버튼, 대기 목록 카드 |
| `--r-panel` 16px | 이음센터 패널·테이블 컨테이너, 데스크톱 프레임 |
| `--r-card` 18px | 답변·후속질문·폴백 카드, 질문 입력 박스, 로그인 카드 |
| `--r-pill` 999px | 필터 칩, 건수 뱃지, "24시간 안내" 필 |

- 간격은 `--sp-*` 스케일(4배수)을 우선 사용. 8의 배수 우선(8pt 그리드)은 유지.
- 그림자는 `--shadow-card`(카드) / `--shadow-raised`(시트·모달·프레임) 두 값만.
- 타이포는 `--t-*` 스케일만. 시민 본문 17px 이상, 관리자 본문 15px 이상.

## 4. 레이아웃 규칙 (시안 추출 조항)

### 4-1. 시민 모바일 (390px 기준)
- 화면 좌우 패딩 20px, 카드 내부 패딩 16px.
- 본문 `--t-body`(17px) 이상, 주요 CTA 높이 **56px**, 카드 반경 `--r-card`.
- 필수 검증 폭 **390px, 430px** — 가로 스크롤·깨짐 0건.

### 4-2. 시민 데스크톱
- **콘텐츠 폭 680px 고정**, 좌우 여백 auto(최소 80px). 중앙 정렬 단일 컬럼.
- 헤더도 680px 컬럼에 정렬(전체 폭 배경 + 680px 내용).
- **카드 내부 구조·타이포는 모바일과 동일하다. 그리드만 2~4열로 확장한다.**
  (분야 카드 2×2→4열, 예시 질문 1열→2열, 답변 카드 내부 신청 방법/정보 영역 1열→2열)

### 4-3. 이음센터 (데스크톱 우선)
- 좌측 사이드바 **216px 고정, 배경 `--color-admin-nav`** (5장 상세).
- 작업 영역 배경 `--color-bg-admin`, 패널·테이블은 흰색 + `--r-panel`.
- 본문 `--t-body-admin`(15.5px) 이상. 콘텐츠 패딩 22px 28px.
- 태블릿(768px)에서 깨지지 않아야 한다.

## 6. 시민 화면 — 응답 4상태 UI (전문)

백엔드 응답은 SUCCESS / FOLLOWUP / FALLBACK / ERROR 4가지 중 하나이며,
**모든 상태에 별도 UI가 존재해야 한다.** 공통 카드 프레임: 흰 배경, 1px `--color-border`,
반경 `--r-card`, 헤더 행(배경 `#F6F9FD`, 하단 1px `--color-border-soft`).

사용자 말풍선: 우측 정렬, primary 채움, 17px 흰 텍스트, 반경 16/16/4/16.
채팅 응답 영역은 `aria-live="polite"`.

### 6-1. SUCCESS — 답변 카드
아래 요소를 모두 포함한다. 하나라도 빠지면 안 된다. 세로 순서 확정:

1. **카드 헤더**: 민원 유형 뱃지(14px 800 primary, `--color-primary-light` 배경 +
   `--color-primary-border` 테두리, 반경 8px) + 우측 **"공식 출처 확인됨"**
   (verify 원형 ✓ 16px + 13.5px 700 `--color-verify-dark`).
2. **요약**(`answer_summary`): `--t-body-lg`. 핵심 기한·수치는 `--color-highlight` 강조(2장).
3. **신청 방법**(`procedure_steps`): 섹션 라벨 15px 800 text-sub. **온라인/방문 2갈래 구조** —
   - 1번 항목 = **온라인 신청** (채널명 + "24시간" 등 가용 시간),
   - 2번 항목 = **방문 신청** (장소 + "평일 9~18시" 등 운영시간).
   - 번호 원 28px primary 채움 흰 숫자, 항목 제목 17px 700 + 보조 15.5px text-sub.
   - 번호 원 사이를 **이음선**(2px dotted `--color-tie-line`)으로 연결 (7장 규칙).
   - 데이터가 2갈래가 아닌 절차형이면 같은 번호+이음선 문법으로 단계 나열.
4. **필요 서류**: 칩형 — 16px 600, `--color-bg-sub` 배경 + 1px `--color-border`,
   반경 `--r-btn-s`. 보조 설명은 괄호로 같은 칩 안에 (예: "전입신고서 (현장 비치)").
5. **정보 셀**: 처리 기간 / 수수료 2열 그리드(모바일도 2열), 담당 기관은 전체 폭 셀.
   셀 = `--color-bg-sub` 배경, 반경 `--r-cell`, 라벨 13.5px 700 text-sub + 값 17px 700.
   담당 기관 셀 우측에 **"우리 동 찾기"** 보조 버튼(outline primary, 44px) — 동 선택 진입점.
   담당 기관은 이름만이 아니라 연락처·운영시간까지 표시한다.
6. **주의사항**(`caution`): 값이 있으면 반드시 표시 — `--color-warning-light` 배경 +
   `--color-warning` 텍스트 박스, 반경 `--r-btn`. 카드당 warning 박스는 이 1개만.
   (시안에 없는 항목이므로 이 조항이 배치 기준: 정보 셀 아래, 출처 블록 위)
7. **출처 블록** — 형태 고정: **`--color-verify-light` 배경 + 1px `--color-verify-border`**,
   반경 `--r-card-s`. 다른 배경·테두리 조합 금지.
   - 헤더 행: "이 답변의 출처" 14px 800 `--color-verify-dark` + 우측 **확인일 도장**
     ("최종 확인 YYYY-MM-DD", 1.5px dashed `--color-verify`, 반경 8px, 13px 700 verify-dark).
   - 출처 목록: KB ID(`--t-mono`, verify-dark) + 문서명 15px (+ 괄호 출처 기관).
8. **딥링크 CTA**: primary 채움 56px, 카드 내 유일한 채움 버튼 (예: "정부24에서 바로 신청 →").
9. **관련 민원 한 줄 제안**: mock에 관련 질문이 있는 경우만 — `#F6F9FD` 배경 행,
   15px text-sub + 인라인 링크 (예: "이사하셨다면 **대형폐기물 배출 예약**도 함께 확인해 보세요.").
10. **만족/불만족 (카드 푸터)**: 상단 1px `--color-border-soft`, "도움이 되었나요?" 16px 600
    text-sub + 우측 "예"/"아니요" 버튼(46px, outline). hover: 예=verify 테두리,
    아니요=primary 테두리. 클릭 직후 상태는 9-2장.

> ⚠️ **출처와 최종 확인일이 없는 답변 카드는 렌더링하지 않는다.** 응답에 출처 필드가
> 비어 있으면 카드 대신 오류/폴백 UI를 보여준다. (SER-003 — KPI "출처 표기율 100%"의
> 프론트 측 보증 장치)

카드 아래 상태 캡션(선택): "방금 답변까지 N.N초&emsp;개인정보 자동 보호 중" 14px faint.

### 6-2. FOLLOWUP — 후속질문 (트리거 `AMBIGUOUS`)
- 단정적인 답변을 **절대 보여주지 않는다.**
- 헤더 뱃지: "확인 질문" (primary-light + primary-border, SUCCESS 유형 뱃지와 동일 문법).
- 리드 문장 `--t-body-lg` (예: "이사와 관련된 민원이 여러 가지예요. 어떤 일부터 도와드릴까요?").
- **선택지 버튼**: 전체 폭, min-height 56px, 흰 배경 + 1.5px `--color-primary-border`,
  반경 `--r-btn`. 제목 17px 700 primary + 보조 설명 14px text-sub (예: "전입신고 하기 /
  이사한 날부터 14일 이내"). hover: 테두리 primary + 배경 `#F6FAFF`.
  지역 조건이 필요한 경우 선택지에 "지역(동)" 옵션을 포함한다 (SFR-004).
- 하단 안내 15px text-sub: "골라도 되고, 질문을 다시 써도 돼요. 선택하시면
  **공식 출처를 확인해** 답해드립니다."
- **선택 직후 상태**: 질문 카드가 요약형으로 전환 — 선택한 칩은 primary 채움 + 우측 ✓ 원
  (`rgba(255,255,255,0.25)` 배경), **미선택 형제는 opacity 0.45** + `--color-border-soft`
  테두리로 남는다. 그 아래 답변 카드가 이어진다.
- 관련 민원이 있으면 답변 카드의 한 줄 제안(6-1-9)으로 잇는다.

### 6-3. FALLBACK — 폴백 4종 (오류가 아닌 "다음 행동" 문법, **빨강 미사용**)
공통 구조: 헤더 뱃지(primary-light 문법) → 리드 문장 `--t-body-lg` →
CTA1(primary 채움 56px) → CTA2(outline primary 56px, 필요시) → 하단 노트 15px text-sub.
모든 폴백에 **사유 안내 + 담당 부서/공식 채널 연결**이 있어야 하며, 기관 정보는
이름·연락처·운영시간까지 표시한다 (DAR-002).

| 코드 | 헤더 뱃지 | 리드 방향 | CTA 구성 |
|---|---|---|---|
| `INSUFFICIENT_GROUNDING` | "확인 후 안내" | "아직 확인된 공식 자료가 없어요. 추측 대신 정확한 곳으로 이어드릴게요." | 담당과 전화 + 정부24 보조 |
| `PERSONAL_LOOKUP` | "담당 부서 연결" | "본인 확인이 필요해서 여기서는 알려드릴 수 없어요. 바로 확인할 수 있는 길을 이어드릴게요." | **공식 조회 채널 딥링크가 CTA1** (예: "위택스에서 내 지방세 확인 →") + 담당과 전화 보조 |
| `LEGAL_JUDGMENT` | "전문 상담 연결" | "법적 판단이 필요한 내용이라 담당자 상담이 더 안전해요." | 담당 부서 전화 + 방문 상담 안내 |
| `OUT_OF_SCOPE` | "다른 창구 안내" | "이 분야는 아직 민원이음이 답하지 못해요. 지금은 아래 4개 분야를 안내하고 있어요." | **지원 4개 분야 칩 재안내** + 대표전화 |

- UI 톤은 "죄송합니다/오류"가 아니라 "안전하게 연결해 드립니다".
- 하단 노트에 개인정보 안심 문구를 겸한다 (예: "질문 내용은 저장되지 않았습니다.
  전화 상담은 평일 9~18시에 연결돼요.").
- 폴백 카드에는 출처 블록·도장이 **없다** — 의도된 부재(검증된 답변이 아니므로).

### 6-4. 로딩 / 오류
- **로딩 스켈레톤 — 답변 카드 구조 예고**: 헤더(뱃지 자리 + 확인 뱃지 자리) → 본문 2줄 →
  번호 원 + 텍스트 스텝 2개 → **출처 블록 자리(64px, `--color-verify-light` + 초록 계열
  테두리)**. 스켈레톤 면은 `--color-border-soft`/`#EEF1F6`.
  하단에 스피너(테두리 `--color-primary-border` + primary 상단) +
  "공식 자료에서 확인하고 있어요. 보통 3초 안에 답해드려요." 16px 600 text-sub. (PER-001)
- **네트워크 오류 — 재시도가 주인공**: 헤더 뱃지만 danger 톤("연결 오류",
  `--color-danger` 텍스트 + `--color-danger-light` 배경). 리드: "연결이 잠시 끊겼어요.
  **작성하신 질문은 그대로 남아 있습니다.**" CTA1 "다시 시도"(primary 채움),
  CTA2 "전화로 문의 044-120"(outline). 하단 노트로 통신 상태 안내.
- 10초 초과 시 타임아웃 안내 + 재시도로 전환. 무한 스피너 금지.

### 6-5. 만족/불만족 — 모든 응답 공통
- SUCCESS뿐 아니라 **FOLLOWUP·FALLBACK에도** 노출한다 (폴백 불만족 = 과잉 폴백 판정 데이터).
- 클릭 직후: 선택 버튼만 활성 형태(예=primary 채움 ✓ 등), 미선택 버튼 opacity 0.45,
  **둘 다 즉시 disabled.** 좌측 문구가 "의견이 접수됐어요. 품질 개선에 반영됩니다."
  (16px 600 `--color-verify-dark`)로 전환.
- 불만족 시 FeedbackReasonSheet(하단 시트, `--shadow-raised`): 분야 4개 + 사유 코드
  선택형 라디오만. **자유 텍스트 입력란 없음.** 전송 데이터에 질문 원문 미포함.

## 7. 시그니처 기호 — 이음선 · 출처 도장 (v2 검인 시스템 대체 개정)

### 7-1. 이음선
- 형태: **2px dotted `--color-tie-line`**, 수직선.
- 용도: **절차 단계 연결 전용** (신청 방법의 번호 원 사이). **화면당 1회.**
- 다른 용도(장식 구분선, 타임라인, 리스트 연결 등) 사용 금지.

### 7-2. 출처 도장 (초록 파선 테두리 — 구 파랑 SealMark 폐기)
- 형태: **1.5px dashed `--color-verify` 테두리** + `--color-verify-dark` 텍스트.
  원형 이중 테두리 인장(v2 SealMark)이 아니라 **파선 사각 도장**이다.
- **크기 3종 (이 외 크기 금지):**
  1. **인라인 12~13px** — 확인일 칩, "URL 대조 완료" 칩 (반경 8px).
  2. **카드 14px** — 출처 블록 헤더의 확인일 도장.
  3. **승인 스탬프 ~104px** — KB 후보 **승인 직후에만.** 카드 우상단 `rotate(-8deg)`,
     2px dashed `--color-verify`, 반경 `--r-btn`, 배경 `rgba(242,250,245,0.9)`.
     내부 3줄: "승 인"(17px 800, 자간 0.14em) + 날짜 + **승인자 실명**.
- **남용 한도: 카드당 도장 1개, 화면당 최대 2개. 도장은 초록 외 색 금지.**
  로딩 스피너·버튼·빈 상태 장식으로 사용 금지.
- **승인 = 도장이 찍힌다** (v2 검인의 승인 연출 유지, 색·형태만 시안 기준으로):
  KB 후보 승인 클릭 직후 승인 스탬프가 우상단에 **scale 1.6→1.0, 200ms ease-out**으로
  찍힌다 (11장 허용 목록). "승인 도장이 찍힌 문서만 시민 답변에 사용됩니다"라는
  서사를 이음센터↔시민 화면이 공유한다.

## 8. 시민 첫 화면 (v3.1 개정 — 구조는 v2 유지, 색·간격·반경·타이포만 v3 토큰)

3. **검색 밴드** — `--color-primary-light` 틴트 배경 **전체 폭**, 내용은 680px 컬럼:

3. 시간 표기 통일: "평일 09:00~18:00" 형식 하나로 (현재 "평일
   9~18시"와 혼용).

[브랜드 워드마크 규칙 통일]
4. 두 화면군의 워드마크를 같은 문법으로: "민원" --color-text +
   "이음" --color-primary / "이음" --color-primary + "센터"
   --color-text. 공유되는 "이음"의 파랑이 브랜드 실이 된다.
   "세종"은 앞에 --color-text-sub 일반 웨이트. 관리자 사이드바의
   흰 변형에서는 "이음"만 밝은 하늘색 톤. 전 위치(헤더, 사이드바,
   관문, 푸터, favicon 병기 텍스트) 동일 적용.

[시민 대화 화면]
5. 하이라이트 여백 정리: 강조 배경 안팎에 불필요한 공백이 들어가
   " 14일 이내 ", "과태료( 5만 원 이하 )"처럼 떠 보인다. 공백
   없이 원문에 밀착, 패딩 1px 4px만. 괄호는 하이라이트 밖에.
6. 신청 방법 단계의 설명 줄("정부24에서 24시간 신청할 수 있어요")
   색을 파란 계열 → --color-text-sub로. 본문 파랑은 링크 전용
   원칙 유지.
7. "함께 확인해 보세요" 칩이 입력창처럼 보인다 — 우측에 화살표
   아이콘(→)을 넣어 누르는 버튼임을 표시, hover 시 primary-tint
   배경.
8. 출처 스트립에서 KB ID 표기 제거. 구성: 체크 아이콘 + "공식
   출처 확인" + 문서명(semibold) + 확인일 + 원문 보기. KB ID는
   시민 화면 어디에도 표시하지 않되 데이터·이음센터에는 유지.

## 부록 B. 구현 단계 변경 반영 (Q-PM-DEMO-001, Q-MVP-002/D-059 — 2026-07-24 append)

위 본문은 제출 기준선(7/17 PDF 7.4/7.5, 데모 #4→#5 연결)을 따른 설계
서술로 보존한다. 구현 단계에서 아래가 우선한다 (사유: 개인정보 최소수집
강화 — 상세는 CLAUDE.md §15).

1. §15 데모 표의 #4→#5 연결은 기준선 서술이다. 현재 #5는 근거 부족 질문
   ("침대 2인용 프레임 배출 수수료" 계열)이 큐에 도착하는 흐름으로
   재구성되었고, actual 경로에서만 완주를 검증한다.
2. 폴백 카드 하단 저장 고지: INSUFFICIENT_GROUNDING만 "개인정보를 가린 채
   30일간만 보관", PERSONAL_LOOKUP·LEGAL_JUDGMENT·OUT_OF_SCOPE는 "질문
   내용은 저장되지 않았습니다".
3. 이음센터 KB 후보 판정 바: fixture 모드에서는 승인·반려 버튼 비활성 +
   사유 캡션("시연용 샘플 데이터는 승인·반려 판정을 지원하지 않습니다").
   승인 스탬프(§7-2 ③형)·완료형 전환은 actual 모드 전용 연출이 된다.
4. 전 화면 최상단 fixture 배너: 앰버(warning) 톤 "시연용 샘플 — 공식
   데이터 아님" — 공지 배너(primary 톤)와 시각적으로 구분한다.
