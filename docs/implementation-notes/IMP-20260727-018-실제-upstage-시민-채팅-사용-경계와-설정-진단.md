## 5. 원인과 설계 경계

### 확인된 원인

1. `create_local_app()`은 `_compose_optional_grounded_chat_runtime()`을 호출한다.
2. grounded runtime의 generator는 `ChatService(answer_generator=...)`로 전달된다.
3. `QuestionClassifier`, classifier settings/client/ledger는 actual 평가 runner에서 동작한다.
4. local factory에는 classifier runtime factory가 없고
   `ChatService(question_classifier=...)` 인수도 전달하지 않는다.

따라서 grounded answer generation은 설정으로 켤 수 있지만, 시민 API의 AI 질문분류는 설정만으로
켤 수 없다.

### 후속 수정에 필요한 경계

- combined exact profile 로드
- generator와 classifier가 공유하는 `ProviderAttemptLedger`
- classifier를 `ChatService(question_classifier=...)`로 전달
- lifespan에서 classifier client 종료
- disabled/partial/invalid profile은 provider 0
- 개인정보·policy path outbound 0과 combined cap 40 회귀

## 6. 지금 가능한 실제 AI 답변 생성 설정

ignored `apps/api/.env`에서 다음 exact non-secret profile을 사용한다.

```dotenv
LLM_PROVIDER=upstage
LLM_MODEL=solar-pro3
LLM_BASE_URL=https://api.upstage.ai/v1
LLM_TIMEOUT_SECONDS=8
LLM_MAX_RETRIES=0
LLM_MAX_CONCURRENCY=1
LLM_MAX_INPUT_TOKENS=4096
LLM_MAX_OUTPUT_TOKENS=1024
LLM_RUN_ATTEMPT_CAP=30
UPSTAGE_SYNTHETIC_EVALUATION_MODE=false
UPSTAGE_CLASSIFIER_MODE=false
UPSTAGE_GROUNDED_CHAT_MODE=true
```

`LLM_API_KEY`는 기존 ignored assignment를 그대로 사용한다. 값은 shell, Git, 문서에 복사하지 않는다.
API를 완전히 종료한 뒤 다시 시작해야 설정이 반영된다.

### 호출되는 경우

- 지원 4분야
- 개인정보 마스킹 성공
- ACTIVE/OFFICIAL KB 검색과 근거 gate 성공
- 위 exact profile과 key 유효

### 호출되지 않는 경우

- FOLLOWUP, PERSONAL_LOOKUP, LEGAL_JUDGMENT, OUT_OF_SCOPE, CIVIC_SCOPE_GAP
- privacy unresolved 또는 근거 부족
- provider timeout/HTTP/JSON/schema/fact 검증 실패

실패 시 공식 TEMPLATE 응답과 서버 소유 출처로 폴백한다.

## 11. 인간이 반드시 알아야 하거나 승인할 내용

- AI 질문분류는 local API runtime wiring 보완 전에는 실제 시민 요청에서 사용되지 않는다.

- UI의 `AI로 정리한 공식 안내`와 response `answer_mode=GENERATED`가 실제 생성 성공 증거다.
