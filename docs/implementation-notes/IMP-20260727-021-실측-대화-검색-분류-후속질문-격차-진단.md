## 5. 설계 결정과 대안

### 권고안 — bounded hybrid RAG-lite

1. PII·PERSONAL_LOOKUP·LEGAL_JUDGMENT fast path는 현재 서버가 유지한다.
2. 안전한 질문만 classifier에 보내되, 서버가 ACTIVE/OFFICIAL KB의 `topic_id`, 제목과
   승인된 질문 예시만 bounded catalog로 제공한다.
3. 모델은 closed `route`, `intent`, allowlisted `topic_id`, `pending_slot`만 제안한다.
4. 서버가 topic ID의 ACTIVE/OFFICIAL·intent 일치를 다시 검증하고 정확한 레코드를 가져온다.
5. grounding은 단순 원문 token overlap이 아니라 검증된 topic selection과 질문-레코드
   적합성으로 재정의한다.
6. 답변 생성기는 현재 masked question과 선택된 최소 KB만 사용하고, 출처·기관은 계속 서버가
   결합한다.
7. 후속질문은 full transcript가 아니라 기존 context v2의 topic/intent/region/slot만 사용한다.

### 이유

- ACTIVE 20건 규모에서는 embedding·vector DB 없이도 topic catalog가 충분히 작다.
- `장롱`, `냉장고`, `주소이전`, “그 비용은요?” 같은 표현 recall을 높이면서 모델이 임의 KB나
  출처를 만들 권한은 주지 않는다.
- 현재 dependency, migration과 official data lineage를 유지할 수 있다.

### 고려했지만 선택하지 않은 대안

- **A. synonym/규칙표만 확장**: 빠르지만 새 표현마다 재발하며 자유 후속질문을 해결하지 못한다.
- **B. bounded hybrid RAG-lite**: 권고. 새 production dependency·DB migration 없이 현재 20개
  KB에 적합하다.
- **C. embedding/vector RAG**: KB가 수백 건으로 늘면 유리하지만 embedding provider, 비용,
  pgvector migration, 재색인·version/rollback이 필요해 현재 MVP에는 과하다.
- **D. 모델이 전체 답변·출처를 자유 생성**: 공식 근거·source authority 원칙을 위반해 제외한다.

### 미실행 검증과 이유

실제 Upstage 호출은 추가 attempt·비용과 scope-gap DB row를 만들 수 있어 수행하지 않았다.
running process의 소진 counter는 공개 진단 endpoint가 없어 직접 확인하지 못했다. 다만
구성은 combined profile이고, 보고된 generic FOLLOWUP은 코드상 classifier unavailable,
timeout, invalid response 또는 cap 소진 때의 정확한 fail-closed 결과다.
## 9. 보안·개인정보·접근성·성능 영향

- Privacy: 전화번호는 `[전화번호]`로 치환되고 원 숫자 0인 SafeQuestion만 이후 단계로 간다.
  사용자의 화면 말풍선에는 입력이 탭 메모리로 보일 수 있지만 DB/provider에는 masked text만
  전달된다. 전화번호가 포함돼도 안전한 나머지 질문에 답하는 현재 동작은 정책상 허용된다.
- Security: 모델은 source·retention·candidate를 결정하지 않는 기존 권위를 유지한다.
- Accessibility: 지역 선택을 항상 보이게 할 경우 label, 44px target, keyboard/focus와
  screen-reader 상태 문구를 함께 검증해야 한다.
- Performance/cost: hybrid topic selector는 현재 classifier 호출을 재사용해 호출 수를 늘리지
  않는 방향이 우선이다. process cap 변경은 비용 결정이므로 인간 승인 전 변경하지 않는다.

## 11. 인간이 반드시 알아야 하거나 승인할 내용

- 현재 문제는 “AI를 안 써서”가 아니라 AI가 지원 분야까지만 고른 뒤 lexical 검색이 다시
  실패하는 이중 경계 문제다.
- 범위 밖 행정 질문이 generic FOLLOWUP으로 나온 것은 정상 정책 결과가 아니다. 정상이라면
  `CIVIC_SCOPE_GAP`이고 `/admin/failures`의 별도 지원 범위 검토에 들어간다.
- process lifetime classifier 20/combined 40 상한을 소진하면 같은 generic FOLLOWUP이 나오므로
  긴 UAT 세션에는 운영 정책 결정이 필요하다.
- 지역·증명서 선택지는 사용자에게 보이는 행동이므로 구현 전 Q-UX 결정을 확정해야 한다.
- full vector RAG는 지금 바로 필요하지 않다. bounded hybrid RAG-lite가 현재 규모의 추천안이다.
