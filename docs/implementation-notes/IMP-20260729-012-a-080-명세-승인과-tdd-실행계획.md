## 5. 설계 결정과 대안

### 선택

하나의 shared prompt를 compact하게 다시 쓰고 다음을 추가한다.

- `SUPPORTED`, `NO_TOPIC_MATCH`, `CIVIC_SCOPE_GAP`, `NON_CIVIC`,
  `NEEDS_FOLLOWUP`의 의미
- 가장 좁은 covered catalog row 우선
- coverage exclusion의 binding 규칙
- 기존 exact tuple·intent·uppercase `NONE` 보존

### 이유

DeepSeek transport, JSON envelope, parser, enum shape와 catalog 검증은 A-079 9/9로 확인됐다.
남은 차이는 분류 의미에 있고, provider-neutral prompt 한 곳을 고치면 Upstage와 DeepSeek의
계약 drift 없이 동일한 server trust boundary를 유지할 수 있다.

### 고려했지만 선택하지 않은 대안

- DeepSeek 전용 prompt fork: 공급자 간 drift와 회귀 위험 때문에 제외.
- parser 관대화: 서버 신뢰 경계를 약화하므로 제외.
- 개별 실패를 추정해 fixture-specific rule 추가: aggregate evidence로는 어떤 3건인지 알 수
  없고 과적합이므로 제외.
- 즉시 live rerun: 명세 승인은 비용·외부 호출 승인이 아니므로 제외.
