## 5. 설계 결정과 대안

### 선택

다음 순서를 권장한다.

1. local `main`을 private GitHub에 동기화한다.
2. provider payload를 저장하지 않는 bounded 진단으로 인증·model access·response/transport 실패
   범주를 좁힌다.
3. 새 인간 승인 뒤 actual selector corrective run을 정확히 한 번 실행한다.
4. 성공 시 local Web에서 사용자가 제시한 자연어 질문·후속질문·scope-gap/admin queue UAT를 한다.
5. provider-zero 성능 Phase A와 manual 접근성/발표 리허설을 닫는다.

### 이유

현재 가장 큰 사용자 체감 격차는 코드·DB가 아니라 provider actual 품질 증거다. public deploy나
고급 기능보다 이를 먼저 닫아야 “AI가 붙은 자연스러운 채팅”을 실제로 주장할 수 있다.

### 고려했지만 선택하지 않은 대안

- provider actual을 건너뛰고 UI 기능 추가: 핵심 품질 불확실성을 숨겨 폐기.
- 곧바로 public deploy: remote target/auth/backup/CORS 운영 gate가 남아 폐기.
- current local event 통계를 KPI로 사용: 사용자가 이미 금지해 폐기.
- DB reset/reseed 즉시 실행: provider 진단과 독립이며 데이터 증거를 불필요하게 바꿔 보류.
