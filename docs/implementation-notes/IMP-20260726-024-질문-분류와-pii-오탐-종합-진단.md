## 5. 설계 결정과 대안

### 권고

PII/정책/high-confidence 규칙은 deterministic으로 유지하고, 안전하지만 애매한 질문만
strict-enum Upstage classifier에 보내는 hybrid 설계를 권고한다. 모델은 답변·출처·KB·저장
여부를 결정하지 않으며 실패 시 서버 fallback으로 닫는다.

### 이유

deterministic-only의 자연어 recall 한계를 보완하면서 원문/PII, ACTIVE-only와 server-owned
source 원칙을 유지할 수 있다. 모든 질문을 LLM에 보내는 설계보다 비용·지연·오분류 범위가 작다.

### 고려했지만 선택하지 않은 대안

- term table만 확장: 안전하고 저렴하지만 새 표현마다 재발한다.
- 모든 질문을 LLM 단독 분류: 정책·장애·비용·전송 표면이 커지고 ADR-0023 gate를 무너뜨려 거절.
- 현재 outside-scope 질문을 기존 failed queue에 삽입: DB/계약/보관 정책 위반으로 거절.
