## 4. 테스트 전 공통 규칙

### 4.1 결과 기록 항목

각 케이스마다 다음만 기록한다.

| 필드 | 기록 예 |
|---|---|
| 결과 | PASS / FAIL / BLOCKED |
| 화면 상태 | SUCCESS / FOLLOWUP / FALLBACK / ERROR |
| 분류 | 전입 / 증명서 / 폐기물 / 지방세 / 범위 밖 / 알 수 없음 |
| 폴백 사유 | 근거 부족 / 개인별 조회 / 법적 판단 / 지원 범위 공백 / 범위 밖 / 개인정보 미해결 |
| 출처 | 있음/없음, 공식 사이트 이름 |
| AI 표시 | AI로 정리한 공식 안내 / 공식 안내 형식 |
| 관리자 변화 | 없음 / 지원 범위 검토 +1 / 실패 질문 +1 |
| 체감 메모 | 한 문장, 실제 개인정보 금지 |

질문·답변 전체, API key, DSN, context token, 실제 개인정보를 결과표나 화면 캡처에 복사하지 않는다.

### 4.2 기호

- `0`: provider 호출 0 예상
- `G1`: grounded answer 생성 최대 1회
- `C1`: AI 질문 분류 최대 1회
- `C1+G1`: 분류 1회 뒤 답변 생성 최대 1회
- `DB0`: 업무 DB 행 변화 없음
- `EVENT`: 일반 SUCCESS 상호작용 event만 기록 가능하며 원문은 저장하지 않음
- `GAP+1`: 지원 범위 검토 항목이 추가될 수 있음
- `FAIL+1`: 마스킹된 근거 부족 실패 질문이 추가됨

한 API process에서 combined 40회를 넘기지 않는다. 먼저 핵심 18건만 실행하고, 확장 질문은 결과를
검토한 뒤 별도 실행한다. 단순히 한도를 우회하려고 API를 반복 재시작하지 않는다.

### 4.3 독립/연속 테스트

- 표에 `새 대화`라고 적힌 질문은 화면의 **새 대화**를 누른 뒤 실행한다.
- `같은 대화`라고 적힌 질문은 이전 응답의 맥락을 유지한 채 실행한다.
- 전송 중 버튼을 연타하지 않는다. 중복 전송 테스트에서만 명시적으로 수행한다.
- 실제 개인정보는 절대 입력하지 않는다. 보안 케이스는 문서에 있는 합성값만 사용한다.

현재 기억은 전체 대화문이 아니라 15분 서명형 context의 intent, region, topic, pending slot이다.
따라서 `그거요`, `아까 거 말고요` 같은 완전 생략 발화는 PASS 기준에 포함하지 않는다. 그런 문장이

## 12. 근거 부족과 관리자 실제 연동

### 12.1 근거 부족 1건 생성

1. `/admin/failures`를 열고 현재 **근거 부족** 건수를 메모한다.
2. `/chat` 새 대화에서 정확히 한 번 질문한다.

   `매트리스 토퍼만 버리면 수수료가 얼마예요?`

3. 시민 화면 기대:
   - FALLBACK
   - 사유 의미가 “승인된 근거 부족”
   - 임의 수수료 없음
   - 공식 확인 경로 안내
4. `/admin/failures` 새로고침 기대:
   - 근거 부족 건수 +1
   - 마스킹된 질문
   - 상태 `신규`
   - `사유 확정` 버튼
   - KB 후보 적격

같은 질문을 반복 전송하지 않는다. Web의 새 요청은 새 idempotency key가 되어 중복 실패 행을 만들
수 있다.

### 12.2 운영자 단계

1. 역할이 `작성 운영자 · OPERATOR-LOCAL-001`인지 확인한다.
2. 해당 행의 `사유 확정`을 누른다.
3. `사유가 확정되었습니다`와 `KB 후보 생성` 버튼을 확인한다.
4. `KB 후보 생성`을 누른다.
5. `공식 KB 후보 작성` 폼이 열리는지 확인한다.
6. 여기서 중단한다.

현재 “매트리스 토퍼”의 정확한 공식 근거를 별도로 확인하지 않았으므로 임의 수수료·출처를 채워
승인 요청하면 안 된다. 후보 폼은 AI가 사실을 자동 창작하는 화면이 아니라 운영자가 공식 출처를
확인해 작성하는 화면이다.

### 12.3 지원 범위 검토 분리

1. `/chat`에서 `청년 월세 지원은 어떻게 신청하나요?`를 한 번 질문한다.
2. `/admin/failures`의 근거 부족 목록에는 없어야 한다.
3. **지원 범위 검토** 패널에는 `신규`, `자동 후보 생성 없음`으로 보일 수 있다.
4. 계획/제외 결정은 할 수 있지만 즉시 KB 후보나 ACTIVE가 되어서는 안 된다.

### 12.4 미저장 정책 비교

다음 세 질문 전후 실패 질문 총계를 비교한다.

1. `오늘 날씨 어때요?`
2. `내 자동차세 체납액을 조회해줘`
3. `이 행정처분이 법적으로 부당한가요?`

세 질문 모두 `/admin/failures` 행을 늘리지 않아야 한다.

### 12.5 이미 완료된 20번째 ACTIVE 회귀

`침대 2인용 프레임 수수료가 얼마예요?`를 다시 물어 다음을 확인한다.

- SUCCESS
- 10,000원
- 공식 폐기물 출처
- 과거 근거 부족 상태로 회귀하지 않음

19→20 전체 승인 흐름을 다시 만들기 위해 현재 DB를 reset하지 않는다. 새 공식 근거가 없는
후보를 평가용으로 승인하지 않는다.

## 21. AI 내부 구현 세부 — 필요할 때만 보면 되는 내용

- direct keyword는 classifier provider를 건너뛰지만 SUCCESS grounded generator는 사용할 수 있다.

- grounding 실패는 generator 전에 중단하므로 provider 생성 비용이 없다.
- context는 full transcript가 아니라 signed bounded claims다.
