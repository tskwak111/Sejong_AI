## 5. 설계 결정과 대안

### 선택

정책·PII·명백한 의도는 결정론적으로 닫고, 안전하게 마스킹된 애매 질문만 모델이 closed
route를 제안한다. 서버가 이를 재검증한 뒤 retrieval/grounding/저장을 결정한다.

### 이유

자연스러움은 개선하면서도 모델이 안전정책·공식 출처·승인 workflow를 바꾸지 못하게 한다.

### 고려했지만 선택하지 않은 대안

- 모든 질문을 LLM에 전달: PII 선행 차단·예산·장애 격리가 약해 제외.
- 결정론적 keyword만 유지: 실제 한국어 변형 대응이 부족해 제외.
- 모델이 출처/저장 사유 생성: 서버 정본 원칙에 위배되어 금지.

### 데이터 흐름/상태 변화

원문 → PII 마스킹/정책 gate → deterministic route 또는 masked provider suggestion →
ACTIVE/OFFICIAL 검색 → grounding → 서버 구조화 응답이다. NON_CIVIC/PERSONAL/LEGAL/PRIVACY와
FOLLOWUP은 실패 row를 만들지 않는다.

### 오류·빈 상태·롤백

classifier timeout/schema/budget 실패는 저장 없는 domain FOLLOWUP, generator 실패는 전체
template로 닫는다. provider mode를 false로 두거나 관련 commits를 revert하면 기존 deterministic
경로로 돌아간다.
