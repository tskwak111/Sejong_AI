## 5. 설계 결정과 대안

### 선택

`pull → patched Supabase start → admin DSN을 process memory로만 캡처 → backend login 회전 →
API → ready → Web` 순서를 사용한다. 현재 ACTIVE 20 DB는 reset하거나 seed하지 않는다.

### 이유

remote 코드와 ignored local runtime을 먼저 맞추고, 이전 DB 인증 실패만 최소 범위로 복구한다.
질문 분류와 grounded generation의 combined mode는 이미 ignored env에서 정확한 profile로 준비됐다.

### 고려했지만 선택하지 않은 대안

- `db reset`/`.2 seed-cycle`: 현재 ACTIVE 20 승인 결과를 지우므로 선택하지 않았다.
- `.env` 재작성 또는 key/DSN 출력: 기존 준비 상태를 손상하거나 비밀이 노출될 수 있어 금지했다.
- global pnpm 설치: Corepack과 frozen workspace만 사용하므로 불필요하다.

## 13. 인수인계·재현·롤백

### 재현

1. primary checkout에서 `git pull --ff-only origin main`.
2. patched Supabase verify/start.
3. `status -o env` stdout을 변수에만 담아 `DB_URL`을
   `SEJONG_ADMIN_DATABASE_URL` process environment로 전달.
4. `provision_local_database_login.py` 실행 후 admin environment 제거.
5. `run_local_api.py --port 8000` 시작.
6. 별도 PowerShell에서 `/ready` status 200 확인.
7. `corepack.cmd pnpm --filter @sejong-ai/web dev` 후 `http://127.0.0.1:3000`.

### 롤백

foreground process를 `Ctrl+C`로 종료한다. provider를 끄려면 ignored env의
`UPSTAGE_CLASSIFIER_MODE`와 `UPSTAGE_GROUNDED_CHAT_MODE`를 `false`로 바꾸고 API를 재시작한다.
DB/data에는 rollback할 변경이 없다.

### 다음 개발자 시작점

사용자의 pull/provision/API/Web 실행 결과를 확인한다. 실패 시 secret이 아닌 stable error와
status code만 받아 해당 단계부터 진단한다.
