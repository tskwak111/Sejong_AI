## 현재 알고리즘

1. 질문을 개인정보 마스킹한다. 안전한 마스킹 결과가 없으면 `PRIVACY_UNRESOLVED`로 끝내고
   아무 질문 text도 저장하지 않는다.
2. 개인 조회와 법적 판단을 먼저 차단한다. 날씨·맛집 같은 비민원과 모호한 질문도 각각
   OUT_OF_SCOPE 또는 FOLLOWUP으로 끝내 일반 실패 질문을 만들지 않는다.
3. 전입·주민등록, 주민등록 증명서, 대형폐기물, 지방세 일반 안내 중 하나로 분류한다.
   명백하지 않은 안전한 질문만 optional classifier provider를 사용할 수 있다.
4. 해당 intent의 ACTIVE+OFFICIAL KB만 읽어 topic catalog를 만든다.
5. 승인 질문 예시 exact match, intent anchor가 있는 유일 lexical match, 또는 서버 catalog와
   exact topic/coverage가 일치하는 provider semantic 선택만 채택한다.
6. category, public topic ID, coverage pair와 record-specific detail을 다시 검증한다. 선택이
   없거나 모순되면 `INSUFFICIENT_GROUNDING`이다.
7. 이 경우에만 마스킹 질문을 interaction event와 `failed_questions`에 원자적으로 저장하고
   `candidate_eligible=true`, 30일 보관을 적용한다.
8. 같은 UUID `Idempotency-Key` 재시도는 같은 결과를 재사용한다. 별도 요청 ID로 반복된 같은
   문장은 현재 의미 기반 중복 병합을 하지 않으므로 여러 행이 생길 수 있다.

## 저장되지 않는 반례

- `증명서 발급해야 해` → FOLLOWUP.
- `오늘 날씨 어때요?` → NON_CIVIC/OUT_OF_SCOPE.
- `청년 월세 지원은 어떻게 신청하나요?` → 별도 CIVIC_SCOPE_GAP queue.
- `내 자동차세 체납액을 조회해줘` → PERSONAL_LOOKUP, text/event/failed row 0.
- `이 배출 방법이 불법인지 판단해줘` → LEGAL_JUDGMENT, text/event/failed row 0.
- unresolved PII → PRIVACY_UNRESOLVED, 저장 0.
